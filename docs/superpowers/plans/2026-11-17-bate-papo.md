# Bate-papo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** entregar um aplicativo JavaFX Windows e servidor Java para conversa privada por WebSocket.
**Architecture:** Maven com módulos protocol, server e client. Servidor de sala única em memória, cliente assíncrono e pacote jpackage com runtime.
**Tech Stack:** JDK 21, JavaFX 21, Javalin 7.2.4, Jackson 2.23.0, JUnit Jupiter, Maven 3.10.1.
**Spec:** ../specs/2026-11-17-bate-papo-design.md (aprovado pelo usuário em 17/11/2026).

## Global Constraints

- Interface em português, Windows, WSS remoto e WS apenas loopback.
- Código de acesso em memória/variável de ambiente; nunca logar ou salvar no cliente.
- Sem histórico persistente, entrega offline ou reenvio automático de mensagens pendentes.
- Confirmado significa aceito pelo servidor, não lido pelo destinatário.
- Operação em instância única; publicação depende de acesso e nenhum recurso pago será contratado sem autorização.

## Review Focus

- Desconectar durante conexão/reconexão não pode ressuscitar sessão antiga (teste cliente).
- Apelido ocupado após queda precisa recuperar sessão própria sem expulsar outra pessoa (teste servidor/reconexão).
- JSON malformado, campos grandes e inundação não comprometem outras conexões (testes servidor).
- Texto Unicode, multiline e histórico cheio continuam legíveis e limitados (protocolo, cliente e inspeção UI).
- Confirmação perdida deixa resultado explicitamente incerto; nenhum reenvio silencioso (teste cliente).

### Task 1: Protocolo e ambiente reproduzível
**Files:** pom.xml, protocol/pom.xml, protocol/src/{main,test}/java/br/com/batepapo/protocol/*, scripts/{bootstrap,maven}.ps1.
**Interfaces:** Protocol.encode(Event), Protocol.decode(String), Protocol.validateName(String), Protocol.validateText(String), Protocol.serverUri(String); Event record(type,id,name,text,token,session,users,time).
- [ ] Criar testes de roundtrip Unicode, limites, entradas vazias e URLs inseguras; executar e observar falhas.
- [ ] Implementar protocolo JSON com limite de 16 KiB, apelido de 2–24 caracteres e mensagem de até 2000 caracteres.
- [ ] Provisionar JDK/Maven locais com verificação de checksum; executar testes protocol e registrar resultado.

### Task 2: Servidor de sala privada
**Files:** server/pom.xml, server/src/main/java/br/com/batepapo/server/{ChatServer,Room,Main}.java, server/src/test/java/br/com/batepapo/server/ChatServerTest.java.
**Interfaces:** ChatServer(String token, int port), start(), port(), close(); usa Protocol/Event; /chat para WebSocket e /health para saúde.
- [ ] Escrever testes com dois clientes WebSocket reais: autenticação, broadcast, presença, apelido duplicado, sessão retomada e segredo errado.
- [ ] Observar falha; implementar sala sincronizada, token constante, identificação pelo servidor e mensagens de erro em português.
- [ ] Adicionar limites: 64 conexões, 5 mensagens/segundo, autenticação em 10 s, heartbeat e limite de fila por conexão.
- [ ] Testar JSON inválido, tamanho excessivo, envio sem autenticação e presença ao sair; executar suite e registrar.

### Task 3: Cliente assíncrono e interface
**Files:** client/pom.xml, client/src/main/java/br/com/batepapo/client/{ChatConnection,ChatApp,Launcher}.java, client/src/main/resources/chat.css, client/src/test/java/br/com/batepapo/client/ChatConnectionTest.java.
**Interfaces:** ChatConnection(Consumer<Event>,Consumer<String>), connect(uri,name,token), send(text):String, disconnect(), close(); entrega callbacks sem exigir JavaFX nos testes.
- [ ] Criar testes reais contra servidor: ida e volta Unicode, falha de acesso, desconexão intencional e reconexão após reinício.
- [ ] Observar falhas; implementar transporte assíncrono com geração de conexão, backoff limitado a 30 s, autenticação e confirmação com timeout.
- [ ] Implementar tela de entrada e conversa, lista de participantes, envio Enter/Shift+Enter, estados pendente/confirmado/incerto e histórico máximo 500 itens.
- [ ] Executar testes e inspecionar duas janelas JavaFX usando automação de desktop; corrigir problemas observados.
